Why systemd and not screen or nohup

systemd already runs everything on the server. A service written for it starts at boot, comes back after a crash, has its output in journald, and can be confined with one line. A screen session dies at the first reboot and nobody knows it did.

A user of its own

bash
sudo adduser --system --group --home /srv/app app
sudo mkdir -p /srv/app/current /etc/app
sudo chown -R app:app /srv/app

Put the application in /srv/app/current (copy, git clone, or upload). Secrets go in a file only root and the service can read:

/etc/app/env
PORT=8080
DATABASE_URL=postgres://app:…@127.0.0.1:5432/app
NODE_ENV=production
bash
sudo chmod 640 /etc/app/env && sudo chown root:app /etc/app/env

The unit file

/etc/systemd/system/app.service
[Unit]
Description=App
After=network-online.target
Wants=network-online.target

[Service]
User=app
Group=app
WorkingDirectory=/srv/app/current
EnvironmentFile=/etc/app/env
ExecStart=/usr/bin/node server.js
# ExecStart=/srv/app/venv/bin/gunicorn -w 2 -b 127.0.0.1:8080 app:app
Restart=on-failure
RestartSec=3

# Confinement: the service sees only what it needs.
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/srv/app

[Install]
WantedBy=multi-user.target
bash
sudo systemctl daemon-reload
sudo systemctl enable --now app
systemctl status app --no-pager
output
● app.service - App
     Loaded: loaded (/etc/systemd/system/app.service; enabled)
     Active: active (running) since …
   Main PID: 2140 (node)

Note. The application listens on 127.0.0.1:8080 only; the web server in the TLS article is what faces the internet.

Logs and deploying

bash
journalctl -u app -f
journalctl -u app -p err --since "1 hour ago" --no-pager

Deploying a new release with a short interruption: copy the release to a new directory, switch the current link, then restart the service. Rolling back is switching the link again.

bash
sudo -u app rsync -a ./build/ /srv/app/releases/2026-11-10/
sudo ln -sfn /srv/app/releases/2026-11-10 /srv/app/current
sudo systemctl restart app
