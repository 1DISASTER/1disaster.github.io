A web server with automatic TLS

Caddy obtains and renews Let’s Encrypt certificates on its own and proxies to your application. The nginx with certbot alternative is at the end.

Before you start

  • An A record for your domain pointing at your server address, propagated (dig +short prints your address).
  • Ports 80 and 443 open in ufw: sudo ufw allow 80,443/tcp.
  • Your application listening on 127.0.0.1:8080 or another local port.

Caddy

bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf "https://dl.cloudsmith.io/public/caddy/stable/gpg.key" | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf "https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt" | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
/etc/caddy/Caddyfile
app.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8080
}

www.example.com {
    redir https://app.example.com{uri} permanent
}
bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl -I https://app.example.com
output
HTTP/2 200
server: Caddy
strict-transport-security: max-age=31536000

The certificate is requested on first load and renewed automatically before it expires. The log when needed: journalctl -u caddy --no-pager | tail.

The alternative: nginx with certbot

bash
sudo apt install -y nginx certbot python3-certbot-nginx
/etc/nginx/sites-available/app
server {
    listen 80;
    server_name app.example.com;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
bash
sudo ln -s /etc/nginx/sites-available/app /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d app.example.com --redirect -m you@example.com --agree-tos
sudo certbot renew --dry-run
