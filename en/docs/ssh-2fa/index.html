Key and code together

A key alone is strong. A key plus a code from an authenticator app protects you if your machine and its key are stolen together. Apply it to your daily user only, and keep the panel console as the emergency path.

bash
sudo apt install -y libpam-google-authenticator
google-authenticator -t -d -f -r 3 -R 30 -w 3

Scan the QR code with your authenticator app and keep the printed emergency codes. Then:

/etc/pam.d/sshd (append)
auth required pam_google_authenticator.so nullok
/etc/ssh/sshd_config.d/20-totp.conf
KbdInteractiveAuthentication yes
AuthenticationMethods publickey,keyboard-interactive
Match User root
    AuthenticationMethods publickey
bash
sudo sshd -t && sudo systemctl reload ssh

Careful. Test from a second window before closing your session. nullok lets users who have not set a code up yet log in with the key alone; remove it once every user is set up.

Tighter limits

/etc/ssh/sshd_config.d/30-limits.conf
AllowUsers deploy
LoginGraceTime 20
MaxSessions 4
ClientAliveInterval 300
ClientAliveCountMax 2
AllowAgentForwarding no
AllowTcpForwarding local

AllowUsers rejects any other name before a key is even checked. The two timeouts end hung sessions. Agent forwarding is off because a compromised server could use your keys through it to reach other servers; use ProxyJump instead when you need to hop.

ProxyJump from your machine
ssh -J <user>@<ip> <user>@10.8.0.5
