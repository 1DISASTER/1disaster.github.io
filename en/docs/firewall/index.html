What protects what

Your server has a public IPv4 address, and every port a service opens is visible to the whole internet. The firewall inside the operating system decides which ports others can reach. The rule: deny all incoming traffic by default, and allow only the ports you need.

ufw in four commands

Careful. Allow SSH before enabling. Enabling a firewall that denies everything while you are connected over SSH cuts your session and keeps you out.

bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80,443/tcp
sudo ufw enable
sudo ufw status verbose
output
Status: active
Default: deny (incoming), allow (outgoing), disabled (routed)

To                         Action      From
--                         ------      ----
22/tcp (OpenSSH)           ALLOW IN    Anywhere
80,443/tcp                 ALLOW IN    Anywhere

To open a port for one address only (for example a database for another server you own), and to delete a rule:

bash
sudo ufw allow from 203.0.113.10 to any port 5432 proto tcp
sudo ufw status numbered
sudo ufw delete 3

Rate-limiting SSH attempts

ufw limit refuses an address that opens more than six connections in thirty seconds. It complements fail2ban rather than replacing it:

bash
sudo ufw limit OpenSSH

Docker bypasses ufw

Docker writes its own iptables rules, so a port published with -p 8080:80 is open to the world even when ufw denies it. The simplest fix: publish ports on the loopback address only, and put a web server in front of the containers:

bash
docker run -p 127.0.0.1:8080:80 nginx

Details and the DOCKER-USER alternative are in the Docker article.

If you lock yourself out

Open the browser console from the server page in the client panel. The console does not go through the network and the firewall cannot block it. From there:

bash
sudo ufw allow OpenSSH
sudo ufw reload

Or disable the firewall temporarily with sudo ufw disable, then rebuild the rules calmly from an SSH session.
