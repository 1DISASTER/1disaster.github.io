A daily user that is not root

If you currently log in as root, create a daily account and move your key to it. Commands that need privilege take sudo, and root stays for emergencies.

bash
adduser --disabled-password --gecos "" deploy
usermod -aG sudo deploy
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy/
echo "deploy ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/deploy
chmod 440 /etc/sudoers.d/deploy

From a second window, confirm the new login works before anything else:

bash
ssh deploy@<ip>
sudo -n true && echo sudo works

sshd settings in a drop-in file

Do not edit /etc/ssh/sshd_config directly; put your settings in a file under sshd_config.d so they survive package upgrades. This closes password login for good and stops root from logging in directly:

/etc/ssh/sshd_config.d/10-hardening.conf
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
MaxAuthTries 3
X11Forwarding no

Validate the configuration before applying it, then reload the service. The current session is not cut:

bash
sudo sshd -t && sudo systemctl reload ssh
sudo sshd -T | grep -iE "^(passwordauthentication|permitrootlogin)"
output
passwordauthentication no
permitrootlogin no

Note. On Debian the service is also called ssh. If sshd -t prints any error, do not reload until it is fixed.

fail2ban

It bans addresses that keep failing to log in. With key-only login it is a second layer that also keeps the logs quiet. On Debian 12 the sshd jail needs the systemd backend:

/etc/fail2ban/jail.local
[DEFAULT]
bantime  = 1h
findtime = 10m
maxretry = 5

[sshd]
enabled = true
backend = systemd
bash
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
output
Status for the jail: sshd
|- Filter
|  |- Currently failed: 0
|  `- Total failed:     0
`- Actions
   |- Currently banned: 0
   `- Banned IP list:

If you ban yourself by mistake, from the browser console: sudo fail2ban-client set sshd unbanip <your-ip>.

Automatic security updates

Security patches are installed daily without intervention. Automatic reboots are optional; the setting below reboots when needed at 04:00 server time:

bash
sudo dpkg-reconfigure -plow unattended-upgrades
/etc/apt/apt.conf.d/52reboot
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "04:00";
bash
sudo unattended-upgrade --dry-run --debug 2>&1 | tail -n 5

Verify before you close the session

  • A second window logs in as the daily user with the key, and sudo works.
  • ssh -o PreferredAuthentications=password <user>@<ip> is refused at once with Permission denied.
  • sudo systemctl is-active ssh fail2ban unattended-upgrades prints active three times.
  • Take a snapshot from the client panel now: this is the first state worth returning to.
