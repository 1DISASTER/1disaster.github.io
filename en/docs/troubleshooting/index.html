I cannot connect

  1. The server page in the panel: is its state “running”? If stopped, start it. If suspended, open the billing section.
  2. From your machine: ping <ip>. No reply from a running server means the firewall inside the system drops ICMP (normal) or the system is not booting.
  3. nc -zv <ip> 22. “refused” means sshd is down; “timed out” means the firewall or fail2ban is blocking you.
  4. Open the browser console and check from inside with the commands below.
bash
systemctl status ssh --no-pager
sudo ufw status
sudo fail2ban-client status sshd
sudo journalctl -u ssh -n 30 --no-pager

If your address is in the Banned IP list: sudo fail2ban-client set sshd unbanip <your-ip>. If the firewall blocks: sudo ufw allow OpenSSH.

REMOTE HOST IDENTIFICATION HAS CHANGED

Expected only after a reinstall. In that case remove the old fingerprint: ssh-keygen -R <ip>. If you did not reinstall, do not continue the connection and open a ticket from the panel.

The disk is full

bash
df -h /
sudo du -xh / --max-depth=2 2>/dev/null | sort -rh | head -n 15
sudo journalctl --disk-usage

The usual suspects: bloated logs, old Docker images, or piled-up database dumps. Safe cleanup:

bash
sudo journalctl --vacuum-size=200M
sudo apt autoremove -y && sudo apt clean
docker system prune -f   # if Docker is installed

Out of memory and CPU load

bash
free -h
sudo dmesg -T | grep -i "out of memory" | tail -n 5
uptime
top -b -n 1 | head -n 15

An Out of memory line in dmesg means the kernel killed a process to save the system. In order: reduce the application’s use, add a small swap file, or move to a larger plan. Load consistently above the vCPU count means the processor is the limit.

bash
sudo fallocate -l 1G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo "/swapfile none swap sw 0 0" | sudo tee -a /etc/fstab

What to attach to a ticket

  • The hostname or address, and the time the problem started in your time zone.
  • Which of the steps above you tried and their result.
  • An mtr report from your machine if the problem is connectivity.
  • Command output as text, not as screenshots.

Open the ticket from the support section of the panel, linked to the server in question. Never send passwords or private keys in any ticket.
