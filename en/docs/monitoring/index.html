What is worth watching

Four signals are enough for one server: does the site answer from outside, how long it takes, what share of answers are errors, and how much disk and memory are left. Everything else is noise until proven otherwise.

Uptime Kuma: checking from outside

A check from the server itself cannot see the server being down. Run Uptime Kuma on another machine or a second server and point it at your domain. On the same server it is still useful for internal services:

compose.yaml
services:
  kuma:
    image: louislam/uptime-kuma:1
    restart: unless-stopped
    ports:
      - "127.0.0.1:3001:3001"
    volumes:
      - kuma:/app/data
volumes:
  kuma:
bash
docker compose up -d
# then put it behind Caddy: status.example.com { reverse_proxy 127.0.0.1:3001 }

Add an HTTP(s) monitor for your domain every 60 seconds, and a notification to Telegram, email or Discord from the settings page.

Netdata: live readings

bash
wget -O /tmp/netdata-kickstart.sh https://get.netdata.cloud/kickstart.sh
sh /tmp/netdata-kickstart.sh --stable-channel --disable-telemetry

The dashboard is on port 19999 locally. Do not open it to the world; serve it through Caddy with basic auth, or over an SSH tunnel:

bash
ssh -L 19999:127.0.0.1:19999 <user>@<ip>
# then open http://localhost:19999 on your machine

A disk alert with no tools

/usr/local/sbin/diskwatch.sh
#!/usr/bin/env bash
use=$(df --output=pcent / | tail -1 | tr -dc 0-9)
if [ "$use" -ge 85 ]; then
  echo "Disk at ${use}% on $(hostname)" | systemd-cat -p warning -t diskwatch
  # add a webhook here, for example a Discord or Telegram POST with curl
fi
bash
sudo chmod 700 /usr/local/sbin/diskwatch.sh
(sudo crontab -l 2>/dev/null; echo "*/30 * * * * /usr/local/sbin/diskwatch.sh") | sudo crontab -
