What happens after payment

Once payment is confirmed the server is built in the region you chose: resources and an address are reserved, the image of the operating system you chose in the order is copied, the public SSH key you entered is written in, then the server starts and its access is checked. The order page shows each step with its time, and a “your server is ready” email arrives when it completes.

The public IPv4 address and the login name are on the server page in the client panel, with the connect command ready to copy. No password is created and none is emailed.

The first connection

From Linux, macOS, or Windows 10/11 (PowerShell or Windows Terminal, both ship OpenSSH):

bash
ssh <user>@<ip>

The first time, SSH shows the server host key fingerprint and asks whether you trust it. Type yes. The fingerprint is saved in ~/.ssh/known_hosts and you are not asked again unless it changes.

output
The authenticity of host '<ip>' can't be established.
ED25519 key fingerprint is SHA256:…
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes

Careful. If a later connection prints REMOTE HOST IDENTIFICATION HAS CHANGED and you did not reinstall the server, stop, do not continue, and open a ticket. After a reinstall the message is expected; the fix is in the reinstall article.

The first five commands

Confirm you are on the right server, update the system, and install the tools the rest of this guide uses:

bash
hostnamectl
sudo apt update && sudo apt full-upgrade -y
sudo apt install -y ufw fail2ban unattended-upgrades curl htop
sudo timedatectl set-timezone Asia/Qatar
sudo reboot

Rebooting after the first upgrade makes sure the new kernel is the one running. Wait about a minute, then connect again. When the login name is not root, the account has passwordless sudo.

bash
uname -r
df -h /
free -h
nproc
output
6.8.0-…-generic
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        39G  2.1G   37G   6% /
               total        used        free
Mem:           3.8Gi       210Mi       3.4Gi
2

Note. The disk and memory shown match your plan name (for example 2 · 4 · 40 means 2 vCPU, 4 GB RAM and 40 GB NVMe). A small part of the disk belongs to the file system itself.

What next

  1. Initial hardening: a non-root user, password login disabled for good, fail2ban and automatic updates.
  2. The firewall: open only the ports you need.
  3. A snapshot before the first big change, and an off-server backup of what you cannot lose.
