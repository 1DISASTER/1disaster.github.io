مستخدم يومي غير root

إن كان دخولك الحالي root، أنشئ حسابًا يوميًا وانقل إليه مفتاحك. الأوامر التي تحتاج صلاحية تُسبق بـ sudo، وتبقى root للطوارئ.

bash
adduser --disabled-password --gecos "" deploy
usermod -aG sudo deploy
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy/
echo "deploy ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/deploy
chmod 440 /etc/sudoers.d/deploy

من نافذة ثانية، تأكد أن الدخول الجديد يعمل قبل أي خطوة أخرى:

bash
ssh deploy@<ip>
sudo -n true && echo sudo works

إعداد sshd بملف منفصل

لا تعدّل /etc/ssh/sshd_config مباشرة؛ ضع إعداداتك في ملف داخل sshd_config.d فتبقى بعد ترقيات الحزمة. هذا يغلق الدخول بكلمة مرور نهائيًا ويمنع root من الدخول المباشر:

/etc/ssh/sshd_config.d/10-hardening.conf
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
MaxAuthTries 3
X11Forwarding no

افحص الإعداد قبل التطبيق، ثم أعد تحميل الخدمة. الجلسة الحالية لا تنقطع:

bash
sudo sshd -t && sudo systemctl reload ssh
sudo sshd -T | grep -iE "^(passwordauthentication|permitrootlogin)"
output
passwordauthentication no
permitrootlogin no

ملاحظة. على Debian اسم الخدمة ssh أيضًا. إن طبعت sshd -t أي خطأ فلا تعد التحميل حتى تصلحه.

fail2ban

يحظر العناوين التي تفشل في الدخول مرارًا. مع الدخول بالمفاتيح فقط هو طبقة ثانية تقلل الضجيج في السجلات. على Debian 12 يحتاج sshd إلى backend systemd:

/etc/fail2ban/jail.local
[DEFAULT]
bantime  = 1h
findtime = 10m
maxretry = 5

[sshd]
enabled = true
backend = systemd
bash
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
output
Status for the jail: sshd
|- Filter
|  |- Currently failed: 0
|  `- Total failed:     0
`- Actions
   |- Currently banned: 0
   `- Banned IP list:

إن حظرت نفسك بالخطأ، من شاشة المتصفح: sudo fail2ban-client set sshd unbanip <your-ip>.

التحديثات الأمنية التلقائية

تثبّت التصحيحات الأمنية يوميًا دون تدخل. إعادة التشغيل التلقائية اختيارية؛ الإعداد التالي يعيد التشغيل عند الحاجة في الرابعة فجرًا بتوقيت الخادم:

bash
sudo dpkg-reconfigure -plow unattended-upgrades
/etc/apt/apt.conf.d/52reboot
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "04:00";
bash
sudo unattended-upgrade --dry-run --debug 2>&1 | tail -n 5

تحقق قبل أن تغلق الجلسة

  • نافذة ثانية تدخل بالمستخدم اليومي بالمفتاح، و sudo يعمل.
  • ssh -o PreferredAuthentications=password <user>@<ip> يُرفض فورًا بـ Permission denied.
  • sudo systemctl is-active ssh fail2ban unattended-upgrades تطبع active ثلاث مرات.
  • خذ لقطة من لوحة العميل الآن: هذه أول حالة تستحق الرجوع إليها.
