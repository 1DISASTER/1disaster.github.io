ما الذي يستحق المراقبة

أربع إشارات تكفي لخادم واحد: هل يرد الموقع من الخارج، كم يستغرق الرد، كم نسبة الأخطاء، وكم بقي من القرص والذاكرة. كل ما عداها ضجيج حتى يثبت العكس.

Uptime Kuma: الفحص من الخارج

الفحص من الخادم نفسه لا يكشف انقطاع الخادم. شغّل Uptime Kuma على جهاز آخر أو خادم ثانٍ، ووجّهه إلى نطاقك. على الخادم نفسه يبقى مفيدًا لمراقبة خدمات داخلية:

compose.yaml
services:
  kuma:
    image: louislam/uptime-kuma:1
    restart: unless-stopped
    ports:
      - "127.0.0.1:3001:3001"
    volumes:
      - kuma:/app/data
volumes:
  kuma:
bash
docker compose up -d
# then put it behind Caddy: status.example.com { reverse_proxy 127.0.0.1:3001 }

أضف مراقبًا من نوع HTTP(s) لنطاقك كل 60 ثانية، وتنبيهًا إلى Telegram أو البريد أو Discord من صفحة الإعدادات.

Netdata: القراءات الحية

bash
wget -O /tmp/netdata-kickstart.sh https://get.netdata.cloud/kickstart.sh
sh /tmp/netdata-kickstart.sh --stable-channel --disable-telemetry

اللوحة على المنفذ 19999 محليًا. لا تفتحه للعالم؛ اعرضها عبر Caddy بمصادقة أساسية أو عبر نفق SSH:

bash
ssh -L 19999:127.0.0.1:19999 <user>@<ip>
# then open http://localhost:19999 on your machine

تنبيه القرص بلا أدوات

/usr/local/sbin/diskwatch.sh
#!/usr/bin/env bash
use=$(df --output=pcent / | tail -1 | tr -dc 0-9)
if [ "$use" -ge 85 ]; then
  echo "Disk at ${use}% on $(hostname)" | systemd-cat -p warning -t diskwatch
  # add a webhook here, for example a Discord or Telegram POST with curl
fi
bash
sudo chmod 700 /usr/local/sbin/diskwatch.sh
(sudo crontab -l 2>/dev/null; echo "*/30 * * * * /usr/local/sbin/diskwatch.sh") | sudo crontab -
