التثبيت

من مستودع Docker الرسمي، لا من حزمة التوزيعة القديمة. السكربت الرسمي يكتشف Ubuntu أو Debian بنفسه:

bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
newgrp docker
docker run --rm hello-world
output
Hello from Docker!
This message shows that your installation appears to be working correctly.

ملاحظة. عضوية مجموعة docker تساوي صلاحية root على الخادم. امنحها للمستخدم اليومي فقط.

ملف Compose أول

تطبيق مع قاعدة بيانات، ينشر منفذه على العنوان المحلي فقط ليقف أمامه خادم الويب في المقالة التالية:

compose.yaml
services:
  app:
    image: ghcr.io/example/app:1.4.2
    restart: unless-stopped
    ports:
      - "127.0.0.1:8080:8080"
    environment:
      DATABASE_URL: postgres://app:${DB_PASSWORD}@db:5432/app
    depends_on:
      - db
  db:
    image: postgres:16
    restart: unless-stopped
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: app
    volumes:
      - db:/var/lib/postgresql/data
volumes:
  db:
bash
echo "DB_PASSWORD=$(openssl rand -hex 24)" > .env
chmod 600 .env
docker compose up -d
docker compose ps
docker compose logs -f app

Docker وجدار الحماية

Docker يكتب قواعده في iptables قبل ufw، فمنفذ منشور على 0.0.0.0 يصل من الإنترنت حتى لو رفضه ufw. طريقتان:

  1. انشر كل المنافذ على 127.0.0.1 كما في الملف أعلاه، وضع خادم ويب أمامها. الأبسط والأوصى.
  2. أو امنع الوصول الخارجي للحاويات افتراضيًا عبر سلسلة DOCKER-USER، واسمح بما تحتاجه يدويًا:
bash
sudo iptables -I DOCKER-USER -i eth0 ! -s 127.0.0.1 -p tcp --dport 8080 -j DROP
sudo apt install -y iptables-persistent
sudo netfilter-persistent save

التنظيف والتحديث

bash
docker compose pull && docker compose up -d
docker system df
docker system prune -f
docker volume ls

أحجام الحاويات والصور القديمة تملأ قرص NVMe بصمت؛ شغّل prune دوريًا، ولا تحذف volumes إلا بعد نسخها.
