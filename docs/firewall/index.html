جدار الحماية على مستوى النظام

ufw على Ubuntu و Debian: ارفض كل شيء، اسمح بما تحتاجه، لا تغلق الباب على نفسك، وانتبه لما يفعله Docker.

ما الذي يحمي ماذا

خادمك يحمل عنوان IPv4 عامًا، وكل منفذ تفتحه خدمة عليه يصبح مرئيًا للإنترنت كله. جدار الحماية داخل النظام هو ما يقرر أي المنافذ يصل إليها الآخرون. القاعدة: ارفض كل شيء وارد افتراضيًا، واسمح بالمنافذ التي تحتاجها فقط.

ufw في أربعة أوامر

انتبه. اسمح بـ SSH قبل التفعيل. تفعيل جدار يرفض كل شيء وأنت متصل عبر SSH يقطع جلستك ويمنع عودتك.

bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80,443/tcp
sudo ufw enable
sudo ufw status verbose
output
Status: active
Default: deny (incoming), allow (outgoing), disabled (routed)

To                         Action      From
--                         ------      ----
22/tcp (OpenSSH)           ALLOW IN    Anywhere
80,443/tcp                 ALLOW IN    Anywhere

لفتح منفذ لعنوان واحد فقط (مثلًا قاعدة بيانات لخادم آخر تملكه)، وحذف قاعدة:

bash
sudo ufw allow from 203.0.113.10 to any port 5432 proto tcp
sudo ufw status numbered
sudo ufw delete 3

تقييد معدل محاولات SSH

ufw limit يرفض العنوان الذي يفتح أكثر من ست محاولات في ثلاثين ثانية. يكمّل fail2ban ولا يغني عنه:

bash
sudo ufw limit OpenSSH

Docker يتجاوز ufw

Docker يكتب قواعده مباشرة في iptables، فمنفذ منشور بـ -p 8080:80 يُفتح للعالم حتى لو رفضه ufw. الحل الأبسط: انشر المنافذ على العنوان المحلي فقط، وضع خادم ويب أمام الحاويات:

bash
docker run -p 127.0.0.1:8080:80 nginx

التفاصيل والبديل عبر DOCKER-USER في مقالة Docker.

إن أغلقت الباب على نفسك

افتح شاشة المتصفح من صفحة الخادم في لوحة العميل. الشاشة لا تمر عبر الشبكة ولا يحجبها الجدار. منها:

bash
sudo ufw allow OpenSSH
sudo ufw reload

أو عطّل الجدار مؤقتًا بـ sudo ufw disable ثم أعد بناء القواعد بهدوء من جلسة SSH.
