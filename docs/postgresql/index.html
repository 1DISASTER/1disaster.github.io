PostgreSQL على خادمك

التثبيت

bash
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable --now postgresql
psql --version
output
psql (PostgreSQL) 16.x

المنفذ 5432 يستمع على 127.0.0.1 افتراضيًا، وهذا ما تريده. لا تفتحه في الجدار ما لم يتصل خادم آخر تملكه، وحينها اسمح لعنوانه وحده.

قاعدة ومستخدم للتطبيق

bash
sudo -u postgres psql <<'SQL'
CREATE ROLE app LOGIN PASSWORD 'a long random password';
CREATE DATABASE app OWNER app;
SQL
psql "postgres://app:a long random password@127.0.0.1:5432/app" -c 'select now()'

كلمة المرور تذهب إلى /etc/app/env (مقالة systemd) لا إلى الكود. المصادقة عبر الشبكة المحلية تتطلب كلمة مرور بـ scram-sha-256، وهو الافتراضي في الإصدار 16.

إعدادات تناسب الذاكرة

القاعدة المعروفة: shared_buffers نحو ربع الذاكرة، effective_cache_size نحو ثلاثة أرباعها، و work_mem صغيرة لأنها تُضرب في عدد الاتصالات. لخادم 4 GB يشاركه التطبيق:

/etc/postgresql/16/main/conf.d/digits.conf
shared_buffers = 1GB
effective_cache_size = 3GB
work_mem = 8MB
maintenance_work_mem = 256MB
max_connections = 60
random_page_cost = 1.1   # NVMe
log_min_duration_statement = 500ms
bash
sudo systemctl restart postgresql
sudo -u postgres psql -c "show shared_buffers"

ملاحظة. لخطة 8 GB ضاعف الأرقام الثلاثة الأولى؛ لخطة 16 GB ضاعفها مرة أخرى. ما يُطبع في السجل عن استعلامات أبطأ من نصف ثانية هو أول ما تنظر فيه عند بطء.

نسخة يومية

bash
sudo -u postgres pg_dump --format=custom app > /var/backups/db/app-$(date +%F).dump
pg_restore --list /var/backups/db/app-$(date +%F).dump | head

الصيغة المخصّصة تُضغط وتسمح باستعادة جدول واحد. اجعل سكربت النسخ الاحتياطي في مقالة restic يأخذها، واحذف ما يزيد عن أسبوع محليًا.

bash
find /var/backups/db -name "app-*.dump" -mtime +7 -delete
